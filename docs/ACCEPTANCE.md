# 功能验收与交付记录

验证环境：macOS / Node.js 24.19.0 / Next.js 16.4.2 / React 19.3.1。依赖版本由 pnpm-lock.yaml 固定。

## 已有自动化证据

`tests/core.test.ts` 的 24 项离线测试已通过。包括实际 EPUB ZIP 元数据与 spine、两页 PDF 文本解析、中英 TXT 分章、重复导入检测、无效文件原子失败、段内防剧透裁剪、关键词过滤、章节范围扩展、假引用拦截、向量数学边界、迁移、外键、阅读位置恢复、笔记/高亮/书签/词汇持久化、观点追加、辩论创建与用户插话、无密钥错误、跨站请求拦截、密钥加密、ZIP 恢复与 FTS 重建、无效备份拒绝、TXT 手动分章保持段落 ID。

TypeScript 严格检查通过。Next.js 生产编译与类型检查通过。构建曾提示本地数据目录被广泛文件追踪，已为运行期本地目录添加忽略注释，避免将私人数据当作部署静态资源。

Playwright 场景覆盖 TXT 上传、章节跳转、文本选择、高亮、批注、书签、刷新恢复、缺少 Key 提示、真实 EPUB/PDF 上传及原版视图、390px 移动布局、完整备份下载。**最终生产模式端到端测试通过：1 个完整场景，场景耗时 11.6 秒，总耗时 18.8 秒，无浏览器 pageerror。** 包括实际 EPUB CFI 保存。调试中已修复刷新恢复关闭书房的竞态、EPUB 包内路径转换和开发浮标遮挡手机导航问题。

端到端测试每次用 mkdtemp 创建源码快照，以独立生产服务和全新临时书库运行，不删除已有个人记录，也不把测试书籍混入 data/。一次准备清空测试服务书库的测试命令被自动审批拒绝，已移除全部测试初始化删除逻辑。

## 有 API Key 后的在线验收步骤

1. 在设置保存 Key / Base URL，测试模型列表连接。
2. 点击一段原文，选择教授并执行快速解释、精读、批判、翻译；点击来源卡片核对原文。
3. 在严格模式询问未读结局，确认请求原文和展示来源都不包含未读段落；切换允许全书后才扩大范围。
4. 手动启动向量 / 摘要任务，暂停后重启应用续跑；验证不重复收费处理已缓存的段落。
5. 创建双教授讨论，自动 4 轮、暂停、插话、下一轮、保存纪要；验证两种分析框架有证据且不虚构冲突。
6. 跨书选择两本书生成报告、编辑和保存、退出后继续研究。
7. 选择 AI 语音播放、暂停、继续、取消，再次播放确认缓存命中；双教授音轨确认不同声音。
8. 检查实际 tokens 与服务商账单；确认浏览器响应从不包含保存后的 API Key。

以上在线步骤尚未执行，不以离线测试代替真实模型或真实 TTS 成功证明。
